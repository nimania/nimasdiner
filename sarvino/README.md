# Sarvino — پورتال مدیریت پروژه رستوران

**نشانی عمومی:** https://nimania.github.io/nimasdiner/sarvino/  
**میز آماده‌سازی تغییرات مدیر:** https://nimania.github.io/nimasdiner/sarvino/editor.html  
**داده اصلی:** `sarvino/data.json` در شاخه `main` مخزن `nimania/nimasdiner`

## حدود دسترسی

- صفحه عمومی، بدون لینک از صفحه اصلی و با `noindex` است؛ اما **عمومی و قابل مشاهده با URL مستقیم** است.
- مالک GitHub یا شخصی با مجوز نوشتن در مخزن، تنها کسی است که قادر به **انتشار تغییرات مشترک** است.
- صفحه `editor.html` ورود و احراز هویت ندارد و از نظر URL عمومی است. **هرکس می‌تواند نسخهٔ محلی خودش را بسازد، اما نمی‌تواند بدون مجوز GitHub دادهٔ عمومی را تغییر دهد.**
- ویرایشگر اطلاعات را در `localStorage` مرورگر خودش ذخیره می‌کند؛ هیچ ذخیره‌سازی سروری یا همگام‌سازی زنده‌ای در نسخهٔ فعلی ندارد.
- برای انتشار: در ویرایشگر «کپی داده آماده انتشار» → باز کردن فایل `sarvino/data.json` در GitHub → جایگزین‌کردن محتوای فایل با متن کپی‌شده → Commit changes؛ سپس انتشار GitHub Pages.
- قبل از ویرایش از چند دستگاه، آخرین نسخه منتشرشده را دوباره بارگیری کنید تا داده‌های تازه همکاران از دست نرود.
- روی GitHub Pages هیچ سازوکار معتبر سطح دسترسی برای مشاهده اطلاعات وجود ندارد: **اسناد مالی محرمانه، اطلاعات شخصی، اسکن مدارک، صورت‌جلسه خصوصی و اطلاعات بانکی در `data.json` یا سایر فایل‌های پوشه قرار نگیرد.**

## داده‌های تأییدشده در برابر داده‌های نامعلوم

- تاریخ شروع بازه: **۱۰ نوامبر ۲۰۲۶**.
- تاریخ تعیین تکلیف: **۱ دسامبر ۲۰۲۶**.
- تاریخ افتتاح هدف و **غیرقطعی**: **۱ ژانویه ۲۰۲۷**.
- مکان: Kyrkogatan 13, Sundbyberg، طبق اطلاعات اولیه متقاضی؛ معامله در زمان گردآوری اطلاعات نهایی نشده است.
- مفهوم رستوران ایتالیایی، با تأکید فعلی بر پاستا و ریزوتو.
- تعداد **۳۰ میز** اعلام‌شده توسط مدیر پروژه.
- ظرفیت **۴۰–۵۰ نفر** طبق پاسخ اولیه متقاضی؛ این عدد با تعداد میز باید بررسی و تطبیق داده شود.
- متراژ کل، سالن، آشپزخانه و فضاهای جانبی نامعلوم هستند و عمداً مقدار `null` دارند.
- هزینه اجاره ماهانه **۲۰٬۰۰۰ کرون سوئد** *به‌صورت اعلام متقاضی و تأییدنشده با قرارداد* در `costs` درج شده است، نه پرداخت قطعی.
- قیمت خرید، سرمایه شخصی، بیعانه، تعهدات خصوصی و سایر جزئیات محرمانه در این پورتال منتشر نشده‌اند.

## ساختار `data.json`

| کلید | توضیح |
|---|---|
| `metadata` | تنظیمات انتشار، ارز و زمان |
| `milestones` | نقاط عطف و تاریخ‌های اصلی |
| `team` | نقش‌های کاری بدون اطلاعات تماس خصوصی |
| `facts` | مشخصات رستوران با منبع و درجه اطمینان |
| `checklist` | اقدام‌ها با وضعیت، مسئول، تاریخ و توضیح |
| `costs` | سرفصل‌های هزینه و دوره زمانی با مبلغ اختیاری |
| `quotes` | استعلام‌ها، فروشنده، واحد خرید/مصرف، مقدار و قیمت |
| `actualExpenses` | هزینه‌های واقعی قابل انتشار؛ جدا از برآورد |
| `menuSections` | دسته‌های برنامه منو |
| `recipes` | رسپی‌های استاندارد و فودکاست |
| `updates`, `decisions`, `documents` | گزارش عمومی، تصمیم و پیوند سند عمومی |

### چک‌لیست

وضعیت‌های معتبر:

- `unknown`: وضعیت نامشخص؛ پیش‌فرض همه موارد اولیه و **نه معادل شروع‌نشده**
- `not_started`: بررسی شده و شروع نشده
- `in_progress`: در حال انجام
- `done`: انجام‌شده و تأییدشده
- `blocked`: مانع‌دار

تعداد موارد با وضعیت `done` در داشبورد نمایش داده می‌شود؛ هیچ کاری به‌طور پیش‌فرض انجام‌شده تلقی نشده است.

### مقادیر هزینه‌ها

`amount` مبلغ کرون سوئد یا `null` است. `status` می‌تواند `needs_data`، `estimated`، `quoted`، `committed` یا `paid` باشد. برآورد را با پرداخت واقعی یکی نکنید. سرفصل‌های دوره‌ای هزینه، از فهرست تراکنش‌های واقعی جدا هستند. مبلغ‌های دوره‌های متفاوت را مستقیماً با هم جمع نکنید.

### استعلام و رسپی

در `quotes`:
- `amount`: قیمت **بدون VAT** برای کل بسته بر حسب SEK.
- `packageQuantity`: مقدار قابل مصرف بسته.
- `unit`: واحد مصرف، مانند kg یا litre.
- `date` و `url`: تاریخ و منبع استعلام.

در هر `recipe`:
- `name`: نام غذا؛ `category`: شناسه دسته منو.
- `ingredients`: آرایه‌ای شامل `name`، `quantity` برای هر پرس، `pricePerUnit`، `wasteRate` بین صفر و ۰٫۹۹ و `quoteId` اختیاری.
- اگر `quoteId` به استعلام معتبر اشاره کند، قیمت ماده از `quote.amount / quote.packageQuantity` گرفته می‌شود؛ وگرنه از `pricePerUnit` استفاده می‌شود.
- `labor`، `overhead`، `packaging` هزینه‌های هر پرس؛ `netPrice` قیمت فروش خالص بدون VAT.

`مواد هر پرس = Σ مقدار × قیمت هر واحد ÷ (۱ − افت)`. سپس نیروی کار مستقیم، سربار تخصیص‌یافته و بسته‌بندی به آن اضافه می‌شود. این فرمول برای برآورد اولیه است؛ مبنای واحد، افت و روش تخصیص سربار باید توسط تیم بررسی شود.

## مسیر بعدی توسعه

برای تیک‌زدن و انتشار *کاملاً آنلاین و فوری* با سطح دسترسی «مالک/بیننده»، باید سرویس دیتابیس و احراز هویت مستقلی اضافه شود. تا آن زمان، ابزار فعلی نسخه **ویرایشگر پیش‌نویس + انتشار در GitHub** است و نباید به‌عنوان سامانه چندکاربره با ذخیره مستقیم معرفی شود.

این پوشه عمداً در `sitemap.xml`، منوی عمومی و صفحه اصلی سایت معرفی نشده است.
