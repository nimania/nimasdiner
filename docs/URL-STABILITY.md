# سیاست ثابت‌ماندن نشانی صفحات nimania.net

**تصمیم مالک — ۱۴ نوامبر ۲۰۲۶ / ۲۳ آبان ۱۴۰۵**

از آنجا که فرآیند ایندکس سایت در گوگل آغاز شده است، تا اطلاع بعدی **نشانی هیچ‌یک از صفحات موجود سایت نباید تغییر کند**. این یک قاعدهٔ دائمی برای توسعه‌های بعدی مخزن `nimania/nimasdiner` است، مگر با تأیید صریح مالک.

## قواعد اجرایی

1. آدرس صفحه (دامنه، مسیر، slug، پسوند و ساختار پوشه) را عوض نکنید. صفحهٔ موجود را جابه‌جا، حذف یا به صفحهٔ جدید ریدایرکت نکنید؛ حتی اگر عنوان، متن، امکانات یا طراحی آن تغییر کند.
2. صفحات ایندکس‌شده و صفحاتی را که در حال ایندکس‌شدن هستند حفظ کنید. از 404/410، تغییر به `noindex` و مسدودسازی در `robots.txt` برای مسیرهای قبلی بدون اجازه اجتناب کنید.
3. canonical هر صفحه را به همان آدرس تثبیت‌شدهٔ آن نگه دارید؛ آن را به دامنه یا مسیر دیگری منتقل نکنید.
4. URLهای موجود را از `sitemap.xml` حذف نکنید. اضافه‌کردن صفحهٔ جدید مجاز است، اما URL صفحات قبلی باید باقی بماند و لینک‌های داخلی آن‌ها سالم باشند.
5. در اصلاح ناوبری، ظاهر و محتوای سایت، لینک‌های داخلی، ارجاع‌های بیرونی، و لینک‌های قدیمی دارای fragment (مانند `#get-book`) تا حد امکان سازگار باقی بمانند.
6. تغییر ساختار URL تنها پس از **تأیید صریح مالک** ممکن است. قبل از هر مهاجرت، فهرست دقیق مسیر قدیم و جدید، 301 دائمی، canonical، sitemap، لینک‌های داخلی و شیوهٔ بررسی در Search Console باید مشخص شود.
7. مسیرهای `/get-book/` و `/download.html` به‌عنوان صفحه باقی بمانند؛ حذف دانلود رایگان کتاب به معنی حذف URL آن صفحات نیست. سرویس مستقل تحویل PDF نیز نباید به‌واسطهٔ این سیاست دوباره فعال شود.
8. نشانی عمومی اصلی سایت `https://nimania.net/` است. مسیر `/nimasdiner/` صرفاً سابقهٔ میزبانی GitHub Pages دارد؛ آن را به لینک‌های دامنهٔ اصلی برنگردانید.

## کنترل خودکار

فایل `tools/check-url-stability.mjs`، در GitHub Actions، خروجی تولیدشدهٔ تغییر جدید را با خروجی نسخهٔ پیش از تغییر مقایسه می‌کند و انتشار را در صورت حذف مسیر HTML موجود، تغییر canonical موجود، تبدیل صفحهٔ قابل‌ایندکس به noindex، یا حذف URL قدیمی از sitemap متوقف می‌کند.

- این کنترل دربارهٔ URLهای موجود سخت‌گیر است اما اضافه‌کردن URL جدید را مجاز می‌داند.
- تغییرات متنی، طراحی و بهبود سئو در همان URL مجاز هستند.
- بررسی خودکار جایگزین کنترل لینک‌های داخلی، ریدایرکت‌ها و وضعیت واقعی ایندکس در Search Console نیست.
- پیش از هر انتشار، نتیجهٔ `.github/workflows/pages.yml` را بررسی کنید و کنترل را برای رفع خطا غیرفعال نکنید.

## تصمیم‌گیری هنگام تعارض

اگر درخواست تازه‌ای مستلزم تغییر URL باشد، قبل از انجام آن تعارض را اعلام و تأیید مالک را بگیرید. روش پیش‌فرض: **محتوای تازه، همان نشانی قبلی**.
