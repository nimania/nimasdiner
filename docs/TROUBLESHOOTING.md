# عیب‌یابی و چک‌لیست تحویل

| نشانه | بررسی و اقدام |
|---|---|
| صفحهٔ Drive / unable to open در موبایل | ایمیل قدیمی هنوز به script.google.com می‌رود؛ ایمیل تازه باید به سرویس دریافت برود. استفاده از حالت ناشناس راه‌حل محصول نیست. |
| ایمیل نیامده | رکورد pending، گیرنده، Queue pending/sent/failed، MailApp quota و trigger را بررسی کنید؛ پوشهٔ هرزنامه هم ممکن است علت باشد. |
| فرم نتیجهٔ موفق دارد اما داده نیست | خطای api_register، عنوان پاسخ و نسخهٔ Apps Script را بررسی کنید؛ پیام عمومی تکراری ثبت جدید را تضمین نمی‌کند. |
| API خطا یا JSON parse error | شاید نسخهٔ قدیمی Apps Script پاسخ HTML می‌دهد؛ Save کافی نیست، New version باید Deploy شود. |
| setup خطای ReferenceError حرف فارسی دارد | ابتدای Code.gs را بررسی کنید؛ کد را کامل جایگزین کنید. |
| لینک نامعتبر/منقضی | token ۶۴hex، هش، وضعیت confirmed و انقضا بررسی شود. توکن را در گزارش عمومی ننویسید. |
| دانلود در شمارنده هست ولی مخاطب فایل ندارد | شمارنده فقط آماده‌سازی سمت Apps Script را ثابت می‌کند؛ انتقال و خطای مرورگر را جدا بررسی کنید. |
| دوباره ثبت‌نام نمی‌شود | ایمیل lowercase یکتا است؛ pending بعد از یک ساعت لینک تازه می‌گیرد. برای شروع کاملاً تازه، مالک ردیف دقیق Subscribers را حذف کند. |
| PDF قدیمی است | ID و بایت فایل خصوصی Drive و زمان آخرین upload را بررسی کنید؛ فایل در repo عمومی نباید مرجع جاری باشد. |
| انتشار Worker entrypoint پیدا نمی‌کند | archive باید مسیر dist/server/index.js و .openai/hosting.json را در ریشهٔ بسته داشته باشد. |

## آزمون بدون پیام واقعی

```bash
node backend/tests/flow.cjs
node --check services/delivery/worker/index.js
```

آزمون شبیه‌سازی‌شده تأیید فقط با POST، دریافت خصوصی، شمارنده، تکرار ثبت، تبدیل متن سادهٔ ایمیل، محافظت فرمول، صف سهمیه و API نامعتبر را پوشش می‌دهد؛ تست واقعی میزبانی و شبکه نیست.

## پذیرش یک تغییر اجرایی

- GET لینک، وضعیت را تغییر ندهد؛ دکمهٔ تأیید لازم باشد.
- مخاطب بدون ورود به گوگل و در مرورگر موبایل بتواند PDF بگیرد.
- فایل دریافتی واقعاً PDF و تعداد بایت معقول باشد؛ HTML خطا با پسوند pdf ذخیره نشود.
- invalid/expired token فایل ندهد؛ PDF عمومی در output Pages نباشد.
- رضایت اختیاری، fields، RTL و لینک‌های تماس حفظ شوند.
- وضعیت subscriber، Queue و Events به همان ایمیل آزمایشی مربوط باشند؛ جمع دفعات را با تعداد افراد اشتباه نگیرید.
- هنگام پاسخ به مخاطب خطای سمت سرور را با موفقیت ذخیرهٔ فایل یکی ندانید.

## توسعه‌های بعدی

اولویت‌ها: رسید دریافت کامل مرورگر و خطای دانلود با attempt ID؛ داشبورد خصوصی شمار افراد بدون تست؛ resend مستقل با محدودیت روزانه و دقیقه‌ای؛ ثبت خطای ساختاریافته بدون PII؛ کاهش ریسک ذخیرهٔ ناقص میان status و enqueue؛ ذخیرهٔ فایل باینری/stream به جای base64 برای رشد حجم؛ rate limiting واقعی پیش از ثبت؛ وضعیت bounce ایمیل. هیچ‌یک از این موارد را قابلیت موجود معرفی نکنید.
