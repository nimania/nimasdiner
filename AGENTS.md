# Repository instructions — Nima's Diner / nimania.net

These instructions apply to all future changes in this repository, including automated/AI-assisted changes.

## CRITICAL: Keep all existing public page URLs stable

The owner has started Google indexing of `https://nimania.net/`. **Do not change, rename, move, delete, or redirect an existing public page URL** without the owner's explicit advance approval. Preserve every existing HTML route, even if the title, text, design, product offering, or page purpose changes.

- Keep current path slugs, directory structure, and the site's domain-root routing. Never reintroduce `/nimasdiner/` prefixes on `nimania.net`.
- Edit the content **at the existing URL** rather than moving the page to a new URL. In particular, keep `/get-book/` and `/download.html` working as pages even though free book downloads have been disabled.
- Preserve existing canonical targets, indexable-page status, and indexed URLs in `sitemap.xml`. Do not change `robots.txt` in a way that blocks existing public content.
- Preserve old internal links and externally used deep links; do not create broken links or unnecessary redirects.
- New pages and routes may be added; existing published page routes must remain available.
- If a migration is essential, **ask the owner first**. Only after approval, document the exact old-to-new mapping, 301 redirects, canonical changes, sitemap and internal-link changes, and Search Console verification.
- Never bypass or weaken the URL stability gate merely to make a deployment pass.

## Checks and source of truth

The deployed site is generated by `tools/build-site.mjs` into `site-dist/`; changing only `index.html` will not change the generated homepage. The GitHub Actions test workflow builds both the current revision and its baseline revision, then runs `tools/check-url-stability.mjs` to ensure earlier HTML paths, canonical targets and sitemap locations survive. Maintain this gate when modifying the build.

Read `docs/URL-STABILITY.md` before any routing, SEO, navigation or deployment change. The policy is specifically for public web page URLs; it does not authorize re-enabling the separate free-book delivery API.
